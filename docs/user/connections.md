# 数据库连接

## 1. 功能说明

「数据库连接」用于保存你常用数据库的访问信息（地址、端口、账号、密码等），以便导入、导出、查询、作业、定时任务等模块重复使用，不必每次重新填写。本工具内置支持 **MySQL / MariaDB** 与 **本地 SQLite**。

## 2. 适用场景

- 当前版本功能说明：**已实现**（数据库连接功能完整可用）。
- 什么时候需要「数据库连接」：
  - 首次导入 / 导出 / 查询数据前，必须先有一个可用的连接。
  - 多成员多人共用同一套数据库时，只需维护一套连接配置。

## 3. 操作入口

数据导表工具 → 顶栏/侧栏「新建连接」。

## 4. 操作步骤

### 第一步：新增连接

进入「新建连接」，点击「新增」。「连接名称」填写便于识别的名称（例如「线上销售库」），选择「数据库类型」（默认 MySQL / MariaDB）。

**预期结果：** 出现一个空的连接编辑表单，标题为「新建连接」。

### 第二步：填写连接信息

在表单中填写「主机」「端口」「用户名」「密码」「数据库」。端口 MySQL 默认 `3306`。

**预期结果：** 各项填写到位，字段无缺漏。

### 第三步：测试连接

点击「测试连接」。工具会尝试连接该数据库，并在「数据库」下拉中列出该实例下可用的业务数据库（系统库如 `information_schema`、`mysql`、`sys`、`performance_schema` 会自动过滤）。

**预期结果：** 提示连接测试成功；若连接失败，会显示错误信息（详见《常见问题》）。

### 第四步：保存连接

点击「保存连接」。

**预期结果：** 连接出现在左侧「数据库连接」列表中，之后各模块的同名下拉中都能选用。

### 第五步（可选）：编辑 / 删除连接

在列表中选择某连接后可「删除连接」。编辑时「密码」留空表示不修改原密码。

**预期结果：** 修改或删除后列表同步更新。

## 5. 参数说明

| 参数 | 说明 | 是否必填 | 示例 |
|---|---|---|---|
| 连接名称 | 用于识别该连接 | 是 | 线上销售库 |
| 数据库类型 | 数据库种类（MySQL / MariaDB） | 是 | MySQL |
| 主机 | 数据库服务器地址 | 是 | 192.168.1.10 |
| 端口 | 数据库端口 | 是 | 3306 |
| 用户名 | 数据库账号 | 是 | root |
| 密码 | 数据库密码 | 是 | 你的密码 |
| 数据库 | 默认使用的库名（测试时列出可选业务库） | 推荐 | mall |
| 字符集 | 客户端字符集 | 否 | utf8mb4 |
| 启用 SSL | 数据库启用 SSL 时打开 | 否 | 关闭 |

## 6. 执行结果

- 测试连接成功：状态提示「连接测试成功」。
- 保存成功：列表出现该连接，其他模块下拉可直接选用。

## 7. 注意事项

- 「主机」「端口」「用户名」「密码」填写错误或不匹配都会导致测试连接失败。
- 测试连接时「数据库」下拉会过滤系统库，避免 App 干扰选择；你手动选中的业务库会保留。
- 密码以加密方式保存，他人看不到明文；编辑已有连接时密码留空表示不修改。

## 8. 常见问题

### Q：为什么测试连接失败？

**可能原因：**

1. 主机地址错误。
2. 端口错误（MySQL 默认 3306）。
3. 用户名或密码错误。
4. 该数据库禁止远程连接。
5. 网络或防火墙限制。

**解决方法：** 逐项核对连接配置后重新「测试连接」。

### Q：下拉里为什么没有我想连的库？

「数据库」下拉会过滤系统库（`information_schema` / `mysql` / `sys` / `performance_schema`）。如果你的业务库也没出现，请先确认账号对该库有访问权限。
