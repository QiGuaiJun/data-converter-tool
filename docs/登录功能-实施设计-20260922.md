## 一、设计目标

在**不破坏现有桌面使用方式**的前提下，把单账号 Basic Auth 升级为多用户登录模块：

1. **登录页**替代浏览器原生弹窗，支持登出、显示当前用户、会话超时。
2. **每人一个账号 + 三种角色**，权限落到接口级（因为查询页已能 `DROP` 表）。
3. **审计可追溯**：谁、什么时候、对哪个库执行了什么。
4. **公网可安全暴露**：HTTPS、Cookie 加固、防爆破、CSRF 防护、密钥可固化。
5. **不动现有验收链**（关键约束，见第七节）。

### 明确不做（本期）

- 开放注册（账号由管理员创建）
- 单点登录 / 企微飞书扫码（调查文档档位 C，后续可加）
- 密码找回（管理员重置即可）
- 多租户数据隔离（所有人共享同一套连接与任务，只区分"能做什么"）

## 二、架构总览

```
浏览器                     公网入口                服务进程 (server.py)
┌──────────┐    HTTPS    ┌──────────────┐        ┌────────────────────────┐
│ login.html│ ─────────► │ 反代/平台入口 │ ─────► │ do_GET/POST/DELETE     │
│ 11 个页面  │            │ (TLS 终止)   │        │  ↓ require_auth()      │
└──────────┘             └──────────────┘        │  ├ Basic（脚本/健康检查）│
      ▲                                           │  └ Cookie（浏览器会话）  │
      │ Cookie: dc_session=<token>                │  ↓ require_permission()│
      └───────────────────────────────────────────│  ↓ audit_log()        │
                                                  └────────────────────────┘
                                                          ↓
                                           _users / _sessions / _audit_logs
```

**两条认证通道并存（这是本设计的关键取舍）**

| 通道 | 使用者 | 凭据 | 作用 |
|---|---|---|---|
| Cookie 会话 | 真人浏览器 | `dc_session`（HttpOnly） | 登录页、登出、超时、按角色 |
| HTTP Basic | 脚本 / 健康检查 / 应急 | `ADMIN_USER` + `ADMIN_PASSWORD` 环境变量 | **现有 13 个复跑脚本与 `/api/ping` 零改造** |

Basic 通道仅授予 `admin` 身份、可通过环境变量关闭，且**只在配置了 `ADMIN_PASSWORD` 时启用**（沿用现有语义）。

## 三、数据模型（3 张新表）

沿用现有 `create table if not exists` 风格，落在元数据库 `runtime/data/imports.db`。

```sql
create table if not exists _users (
  id            text primary key,
  username      text not null unique,
  display_name  text not null default '',
  password_hash text not null,          -- scrypt$n$r$p$salt_hex$hash_hex
  role          text not null default 'viewer',   -- admin | operator | viewer
  enabled       integer not null default 1,
  created_at    text not null,
  created_by    text not null default '',
  last_login_at text,
  failed_count  integer not null default 0,       -- 连续失败次数（防爆破）
  locked_until  text                              -- 锁定到期时间
);

create table if not exists _sessions (
  id         text primary key,
  token_hash text not null unique,      -- sha256(token)，明文不落库
  user_id    text not null,
  created_at text not null,
  expires_at text not null,
  last_seen_at text,
  ip         text not null default '',
  user_agent text not null default ''
);
create index if not exists idx_sessions_expires on _sessions(expires_at);

create table if not exists _audit_logs (
  id         text primary key,
  created_at text not null,
  user_id    text not null default '',
  username   text not null default '',
  action     text not null,             -- login/logout/query.run/import.run/...
  target     text not null default '',  -- 连接名/表名/作业名
  detail     text not null default '',  -- SQL 摘要、影响行数、危险等级
  ip         text not null default '',
  status     text not null default 'ok' -- ok | denied | error
);
create index if not exists idx_audit_created on _audit_logs(created_at desc);
```

**密码哈希**：`hashlib.scrypt(password, salt=16B, n=2**14, r=8, p=1)`；校验用 `hmac.compare_digest`。
**会话 token**：`secrets.token_urlsafe(32)`，库里只存 sha256，泄漏库不等于泄漏会话。

## 四、接口设计

### 4.1 新增 `/api/auth/*`

| 方法 | 路径 | 说明 | 豁免认证 |
|---|---|---|---|
| POST | `/api/auth/login` | `{username, password, remember}` → 下发 Cookie | 是（唯一豁免） |
| POST | `/api/auth/logout` | 作废当前会话 | 否 |
| GET | `/api/auth/me` | 返回 `{username, displayName, role}` | 否（未登录返回 401） |
| POST | `/api/auth/password` | 本人改密：`{oldPassword, newPassword}` | 否 |

### 4.2 管理员接口（仅 `admin`）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/users` | 用户列表（不含哈希） |
| POST | `/api/users` | 新建用户 `{username, displayName, password, role}` |
| POST | `/api/users/update` | 改角色 / 启停 / 重置密码 |
| DELETE | `/api/users?id=` | 删除用户（同时作废其全部会话） |
| GET | `/api/audit-logs` | 审计查询（按用户/动作/时间过滤，分页） |

### 4.3 首次启动引导（解决"第一个账号从哪来"）

逻辑：`APP_AUTH_ENABLED=true` 且 `_users` 为空时——
若配置了 `ADMIN_PASSWORD`，用它创建首个 `admin`（沿用 `render.yaml` 现有配置，部署零改动）；
否则生成一次性随机密码并**打印到服务日志**（`runtime/logs`），首次登录后强制改密。

## 七、公网部署强化（这一节决定"能不能放在公网"）

| 项 | 措施 | 理由 |
|---|---|---|
| **HTTPS** | 平台自带 TLS（Render/Railway）或反代 Nginx；服务内检测 `X-Forwarded-Proto=https` 时给 Cookie 加 `Secure` | 明文传密码等于没登录 |
| **Cookie 属性** | `HttpOnly` + `SameSite=Lax` + `Path=/` + `Secure`（HTTPS）+ `Max-Age`（会话 8h / 记住我 7d） | 防 XSS 窃取、防基本 CSRF |
| **CSRF** | 所有写操作要求自定义头 `X-DC-Request: 1`；服务端校验 `Origin`/`Referer` 与 Host 一致 | Cookie 认证下浏览器会自动带凭据，而查询页能 `DROP` 表 |
| **防爆破** | 同用户名连续 5 次失败锁 5 分钟；同 IP 每分钟 20 次登录请求限流 | 公网暴露必然被扫 |
| **密钥固化** | **必须**设置 `DC_MASTER_KEY`（现有代码已支持，见 `server.py:365`） | 容器重建若丢 `.secret_key`，已存的数据库连接密码**全部解不开** |
| **会话持久化** | `_sessions` 落库（同 DATA 卷） | 平台自动重启后用户不掉线 |
| **审计保留** | 默认保留 90 天，随日志清理任务一并 prune | 避免无限增长 |
| **敏感信息** | `/api/connections` 响应永不返回密码；日志已有 `redact_log_text` 脱敏 | 沿用现有防护 |

**平台配置增量**（`render.yaml`）：

```yaml
      - key: DC_MASTER_KEY          # 新增：固定主密钥，务必用平台 secret 存储
        sync: false
      - key: APP_AUTH_ENABLED       # 新增：显式开启
        value: "true"
```

### 12.3 部署形态建议

仓库已有 `Dockerfile`（`python:3.12-slim` + `CMD python server.py`）与 `Procfile`，因此推荐：

```
Nginx（443，TLS 终止 + 反代 127.0.0.1:51978）
  └── docker run（挂载 /opt/dc/runtime 持久化数据）
        └── server.py（HOST=127.0.0.1 PORT=51978 APP_AUTH_ENABLED=true DC_MASTER_KEY=<固定值>）
```

要点：
* **只监听 127.0.0.1**，公网只经 Nginx；不要直接把 51978 暴露到公网（无 TLS）。
* 数据卷 `/opt/dc/runtime`（含 `imports.db`、uploads、exports、`.secret_key`）**必须持久化**。
* `DC_MASTER_KEY` 用固定值注入（容器重建后仍能解密已存的数据库连接密码）。
* 证书：腾讯云免费 DV 证书或 Let's Encrypt（需域名）。

### 12.4 数据库方案（业主已决策 2026-09-22）：应用与 MySQL 同机部署

**决策**：不再连公司内网的 `192.168.7.173`，改用**云服务器本机的 MySQL**（该机 3306 已放通，正好对应这一用法）。
连通性问题随之消失——应用与数据库在同一台机器上，走 `127.0.0.1`，不经过公网。

> ⚠️ **这个决策带来三个必须知晓的后果**（不是反对，是让你在清楚后果的前提下决定）：

| # | 后果 | 说明 |
|---|---|---|
| 1 | **云端库与公司库是两份数据** | 云上 MySQL 是全新空库，与内网 `lcdp_fe` **没有任何关系**。公司其他系统（报表、BI）读的是内网库，**看不到云上产生的数据** |
| 2 | **桌面自动化与现有定时任务全部失效** | 现有「中秋试饮活动」定时任务读的是 `C:\Users\Administrator\Desktop\数据导入\`，云端没有你的桌面；`/api/import/choose-source`、`/api/export/choose-target` 这类本机原生对话框在云端也无意义 |
| 3 | **工具定位改变** | 从"公司数据管道的一环"变成"独立的云端数据处理服务"：同事上传文件 → 转换/导入云端库 → 查询与导出 |

**建议的落地方式**：**云端实例与本地实例并存，不要搬迁**。
本地继续跑公司数据链路（连 `192.168.7.173`，定时任务照旧）；
云端给多市场同事做"上传 → 转换 → 查询 → 导出"，两边互不干扰。这样风险最低，且不破坏已在运行的业务。

## 十三、开放注册的风控设计（业主已确认开放注册）

开放注册在**内网**工具里是便利，在**公网 + 可 `DROP` 生产表**的环境里是风险敞口。
以下 5 道限制**必须同时落地**，缺一不可：
