## 一、4. 业务流程与状态管理

### 4.1 创建 → 编辑 → 保存 → 执行 ✅

- **产品**：服务端 `save_job`（被 `tests/test_jobs_schedule.py:79` 调用）、前端 `jobs.js:481` `saveJob()`、`requestJson("/api/jobs", { method: "POST", ... })`。
- **测试**：`tests/test_jobs_schedule.py:141 test_saved_job_runs_successfully` + 同文件 17 个 `def test_*` 覆盖 happy path。
- **判定**：✅ **产品 + 自动化均覆盖。**

### 4.2 返回、刷新、重新登录后数据保留 ⚠️

- **产品**：
  - 作业 / 调度落 `imports.db`（`tests/test_jobs_schedule.py:24-27` 临时目录注入验证了 schema 隔离）。
  - 登录态：`server.py:8307 session_cookie_header(token, max_age, https)`，`HttpOnly` + `SameSite=Lax` + HTTPS 下 `Secure`，会话 8 小时（README 第 169 行）。
  - 审计日志保留 90 天。
- **测试**：
  - **没有任何"刷新后数据保留"测试。**
  - **没有任何"重登录后 cookie 失效/续期"测试。** `tests/test_p5_auth.py` 已存在但 `grep` 缺覆盖度可见（**待人工打开核验**，仅扫描文件存在）。
  - **没有任何"session 过期时 401"测试。**
- **判定**：⚠️ 产品实现有，但**缺回归测试**。建议新增 `tests/test_e2e_session_persist.py`。

### 4.3 ❌ 取消操作（**产品空缺**）

- **用户期望**：选中"运行中"的作业 → 点取消 → 中断。
- **产品现状**：
  - `server.py` 全文 `grep`（`handle_job_cancel|cancel_job|abort_job|/api/jobs/.+/cancel|runs/cancel|jobCancel`）→ **0 命中**。
  - 唯一定义 "cancel" 的代码段（`server.py:3330 ERROR_CANCELLED`、`7754 cancel_note`、`10695 stop_event`、`3588 _dialog_watchdog`）均与"取消正在运行的作业"无关。
  - 前端 `public/jobs.js:517`：
    ```517:517:public/jobs.js
    $("#cancelJob").addEventListener("click", () => $("#jobDialog").close());
    ```
    ——"取消作业"按钮实为"关闭编辑对话框"。
- **判定**：❌ **产品空缺**。本条问题项 **Q-001**（高优先级，影响用户清单的核心交付标准）。
- **顺带发现**：前端关闭对话框后**不重置** `editingJobId` / `draftSteps`（见 `jobs.js:7-10` 模块级变量；`openJobDialog()` 463 行才重置）—— 下次开 dialog 若**不经过** `openJobDialog`（异常路径：`saveJob` 失败后未弹错对话框就关），状态污染。问题项 **Q-002**。

### 4.4 ❌ 重复提交（**前端缺陷**）

- **用户期望**：狂点"保存"按钮不会创建多条作业。
- **产品现状**：
  - `public/jobs.js` 全文 `grep`（`disabled\s*=\s*true|button\.disabled|this\.disabled|isLoading|loadStart|setLoading|aria-busy`）→ **0 命中**。
  - `public/schedule.js` 同样 0 命中。
  - 对照 `public/sync.js:348 btn.disabled = true; btn.textContent = "运行中";`、`public/export.js:893 runExportButton.disabled = true;`、`public/connections.js:716 btn.disabled = true;`、`public/query.js:197 button.disabled = true;` —— 这些模块**有**，jobs.js / schedule.js **没有**。
- **判定**：❌ **前端缺陷**。问题项 **Q-003**。`saveJob()`（482 行）的 `await requestJson(...)` 期间按钮仍可点，会触发 N 次 POST。

### 4.5 ⚠️ 执行失败后能否正确恢复

- **产品**：服务端有兜底
  - `server.py:7080 _abort_run_failed()`：任何提前退出都收口成"失败"并落库（注释明确写：不会把"运行中"僵尸记录留在库里）。
  - `server.py:7331 should_stop = not step.get("continueOnError", False)` → 多步作业在某步失败时**默认停止**后续 step（用户可改 `continueOnError` 继续）。
  - `tests/test_jobs_schedule.py:218 test_compact_failure_reason_*`：日志侧文字折叠。
- **测试缺口**：
  - **没有"失败后 retry / 重跑单步" 测试入口**。
  - **没有"partial 完成后状态推进" 测试**。
  - **没有"continueOnError=true 时继续跑后续 step" 端到端验证**。
- **判定**：⚠️ 产品有失败兜底路径，**但用户期望的「恢复」语义不明确**——是回到上一步重试？还是整轮重跑？需产品澄清。问题项 **Q-004**。

## 二、5. UI 与交互体验

### 5.1 ⚠️ 字体 / 间距 / 对齐 / 颜色 / 图标是否统一

- **CSS 变量层**：✅ 统一。
  - `public/theme.css:38-80` 定义 `--ink` `--body` `--bg` `--line` `--soft` `--active` `--text` `--blue` 等；`theme-classic.css:35-57` 也定义同名变量但不同色值（**双主题**有意为之）。
  - 字体：CSS 变量 `--serif`（theme.css）、`--mono: Consolas, "Microsoft YaHei", monospace;`（theme-classic.css:57）。
- **风险点 1**：`theme.css` 出现 **80+ 处 `!important`**（grep 命中节录）：`color: var(--ink) !important;` / `border-radius: var(--r-sm) !important;`。这通常是历史 patch 留下的覆写痕迹，导致**特异性失控**。问题项 **Q-005**。
- **风险点 2**：`jobs.html:10-12` 同时引入 3 个 CSS：
  ```html
  <link rel="stylesheet" href="/styles.css?v=20261014_nobg" />
  <link rel="stylesheet" href="/theme.css?v=20261014_backbtn" />
  <link rel="stylesheet" href="/theme-classic.css?v=20261014_nobg" />
  ```
  —— `theme.css` 与 `theme-classic.css` 是**主题切换**，但 `styles.css` 第 2657 行**另一套 `:root`**（`--bg: #f4f8ff`）表明 `styles.css` 内也有半套主题 —— 三层定义可能互相打架。问题项 **Q-006**。
- **图标**：`public/icons/` 19 文件（10 svg + 7 png + 2 html），按命名使用（抽样 `jobs.html` 用 `favicon-32.png` 而非 svg）。**静态看不出命名混乱**。
- **判定**：⚠️ **变量层统一，但优先级与多主题互相覆写存在隐性风险，需 Playwright 跨主题截图比对**。

### 5.2 ✅ 按钮是否有明确的操作含义

- 抽样按钮文本：
  - `jobs.html:46-51`：「新增作业」「编辑作业」「复制作业」「删除作业」「立即执行」「刷新」—— ✅ 含义清晰。
  - `jobs.html:75`：「×」（关闭）—— 配 dialog 上下文可理解，但单独看不直观。
  - `jobs.html:466`：「编辑作业」/「新增作业」同按钮根据状态切换。
- **判定**：✅ 通过。无含糊动词（"处理""操作"等）。

### 5.3 ⚠️ 遮挡 / 溢出 / 错位 / 文字截断（静态分析有限）

- **断点布局**：✅ `styles.css` 有 8 个断点（`720` / `900` / `1050` / `1100` / `1180` / `1250` / `1320` / `1599`），主流分辨率全覆盖。
- **潜在重叠**：
  - `styles.css:2020 @media (max-width: 1599px) { .app-workspace .export-tab-body .two-col { ... } }`
  - `styles.css:2114 @media (max-width: 720px) { ... }`
  - `styles.css:5740 @media (max-width: 1320px) { .app-workspace .import-shell { ... } }` 与 `2073 @media (max-width: 1250px)` 在 1250~1320 区间可能**两套规则同时生效**。
- **静态看不到遮挡**：`zh-CN` + 中文字符截断通常发生在表格 column 设 `width: <px>` + 内容超长 —— 见 `styles.css:5589 .user-table` 表格列定义。
- **判定**：⚠️ **静态扫描只能标出"风险区域"**，最终必须 Playwright 跑 1280/1440/1920/2560 四档截图比对。问题项 **Q-007**（依赖 Playwright）。

### 5.4 ⚠️ 加载 / 禁用 / 悬停 / 选中等状态

- **`styles.css` 状态类齐全**：
  - `:hover` 62 命中（如 `.module-task-toolbar button:not(:disabled):hover`、`.audit-table tbody tr:hover`）
  - `:disabled` 至少 4 命中（`button:disabled, .button:disabled`、`schedule-desktop-toolbar button:disabled`、`user-table button.danger:hover` 等）
  - `.active` 62 命中（ribbon、tree-node、tab、job-item、selected-step 等）
  - `:focus-visible` 至少 1 命中（`.plain-mode-toggle:hover, .plain-mode-toggle:focus-visible`）
- **缺陷**：❌ **没有 `.is-loading` / spinner / aria-busy 通用样式**（grep 命中仅 sync.js:348 一处用 textContent 而非样式切换）。
- **已发现的"状态孤岛"**：见 4.4，jobs.js / schedule.js 在加载中**不修改按钮状态**——视觉上看不出"正在保存"。问题项 **Q-008**。
- **判定**：⚠️ 状态定义齐全，但**使用一致性差**。

- **跨分辨率未跑**：无视觉回归脚本。需 Playwright 跑四档截图 + diff。
- **判定**：⚠️ **桌面覆盖，移动端未知，未做视觉回归**。
