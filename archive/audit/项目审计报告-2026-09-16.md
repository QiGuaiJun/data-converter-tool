## 三、发现的问题（按严重度）

### 🔴 P1 · 新发现：查询模块拒绝带 SQL 注释的语句

**现象**：在「查询」页执行以下 SQL 会被拒绝：

| SQL | 结果 |
|---|---|
| `select 1 as a` | ✅ 接受 |
| `-- 我的查询` + 换行 + `select 1 as a` | ❌ **拒绝**（400） |
| `/* 我的查询 */ select 1 as a` | ❌ **拒绝**（400） |
| `(select 1 as a)` | ✅ 接受 |
| `with t as (select 1) select * from t` | ✅ 接受 |

**误导性提示**：报错说"查询模块当前只允许 SELECT、SHOW、DESCRIBE、EXPLAIN 和只读 WITH 查询"——但用户写的**明明就是 SELECT**。

**根因**：`server.py` 的 `run_readonly_query()` 用 `re.match(r"^[\s(]*([a-zA-Z]+)", sql)` 取首词做白名单判断。注释以 `/` 或 `-` 开头，正则取不到任何字母 → `command` 为空 → 被判非法。

**影响**：中。任何习惯在 SQL 里写注释的用户都会撞上；且提示信息会误导排查方向。

**旁证（模块间不一致）**：同一个带注释的 SQL，在**导出**模块的预览里是**正常执行**的（`ok=true`）。查询模块与导出模块行为不一致。

**修法（很小）**：取首词前先剥离前导注释（`--` 到行尾、`/* */` 块），或把判断改为「去掉注释后是否以白名单关键字开头」。
