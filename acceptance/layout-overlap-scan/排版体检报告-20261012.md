# 导出模块 + 全站组件排版体检报告（2026-10-12）

> 触发：业主反馈「当前页面的组件排版部分组件有叠加重合部分，影响查看观感」（截图红框 = 导出页底栏「预览结果」区域），并要求顺带体检整个项目的组件排版。
>
> 结论：**导出模块查到 5 处真实排版缺陷，全部已修并用几何量复测归零；全站 14 个页面逐一扫描，其余问题均已判定（无真实缺陷）。**

## 一、怎么查的（不是肉眼猜）

写了三个 Playwright 脚本，全部用 `getBoundingClientRect()` 的几何量说话，逐个窗口尺寸真实加载页面：

| 脚本 | 作用 |
|---|---|
| `audit.js` | 全站三类问题扫描：**A 重叠**（互不为祖先的可见元素，交叠占较小者 >10% 且 >200px²）／**B 内容被裁切**（`overflow:hidden` 且 scrollH > clientH+2）／**C 子元素溢出父容器**（父 `overflow:visible`） |
| `verify_export_layout.js` | 导出模块 5 项关键指标，修复前后同一脚本对比（1920/1600/1536/1440/1366/1280/1120 七档宽度） |
| `probe_shell.js` / `diag_dock.js` | 追根因：把主壳、右栏、`.two-col` 行、底栏各格的**计算后栅格与盒模型**全打出来 |

两个关键判定细节（否则会误报）：

1. **裁剪祖先必须算进去**。`overflow:auto` 里被裁掉的宽表格，`getBoundingClientRect()` 仍返回 1790px 宽 —— 不减去裁剪区就会把它误判成「压在隔壁栏上」。修正后导出页的重叠对数从 94 条降到 16 条真信号。
2. **0 高度但内容溢出的元素必须算**。这次的主病灶恰恰是「高度 0、文字溢出」的 `span`，只按 `height>=2` 过滤会整个漏掉。

## 二、导出模块：5 处真实缺陷（已修）

### D1 底栏「预览结果」的统计行塌成 0 高，文字压在表头上 ← **业主红框所指**

**根因**：`.app-workspace .export-dock > div` 只定义了 **2 行**栅格（`auto minmax(0,1fr)`），但每格固定有 **3 个子元素**：`<strong>标题</strong>`、`<span>统计</span>`、内容区。于是：

- 「预览结果」格 → 计算后行高 `24.79px / 0px / 358.59px`：`span` 落进 `1fr` 行被**压成 0 高**，而它 `overflow:visible`，22px 的文字直接溢出去**压在表头行上**（相交 12292px²，占表头 64%）。实拍可见表头「核销时间／时间／权益名称…」上叠着一行残缺灰字。
- 「导出结果」格 → `24.79px / 328.91px / 29.69px`：`span` 反而吃掉整行 1fr，日志 div 被挤到**隐式第 3 行**贴底。

**修法**（`public/styles.css`，`.app-workspace .export-dock > div`）：栅格行改为 `auto auto minmax(0,1fr)`，与 3 个子元素一一对应。
**副修**：同处 `.table-wrap` / `.logs` 的 `height:100%` 已删除（它按栅格区高度算，再叠加 `margin-top:8px` 就比区高高 8px，被格子的 `overflow:hidden` 裁掉表格最后 8px），改由栅格默认 `stretch` 撑满「区高 − margin」。

复测（1440×900）：统计行 **0px → 22px**，与表头相交 **12292px² → 0**，内容裁切 **8px → 0**；栅格行变为 `24.79 / 21.69 / 268.52`，两格对称。

### D2 「预览 / 开始导出」按钮被挤出窗口，且**页面不产生横向滚动条 → 完全点不到**

**根因**：`.app-workspace .export-shell { grid-template-columns: minmax(700px,1fr) minmax(650px,.95fr) }` → 最小合计 **700+650+12 = 1362px**。而 `.app-workspace` 可用宽 = 视口 − 216px 侧栏：

| 视口 | 可用宽 | 右栏 x 范围 | 「开始导出」x 范围 | 可见？ |
|---|---|---|---|---|
| 1920 | 1704 | 1097–1904 | 1771–1861 | ✅ |
| 1600 | 1384 | 948–1598 | 1465–1555 | ✅ |
| **1536** | 1320 | 948–1598 | **1465–1555 → 视口外** | ❌ |
| **1440** | 1224 | 948–1598 | **1450–1540 → 视口外** | ❌ |
| **1366** | 1150 | 948–1598 | 视口外 | ❌ |

即 **1366 / 1440 / 1536 这三种最常见的笔记本宽度下，整个「开始导出」按钮在窗口外**；因为溢出被容器裁掉（`documentElement.scrollWidth == innerWidth`，`横向溢出 = 0px`），**连横向滚动都滚不过去**。

**修法**：最小合计降到 **1012px**（`minmax(440px,1fr) minmax(560px,.95fr)`），与 `.app-workspace .import-shell`（500+500+12=1012）对齐。复测七档宽度下按钮均回到视口内（1440 时 x 1291–1381）。

### D3 「为导出的文件名增加前缀」输入框撑破格子，压住「后缀：」

**根因**：`.export-tab-body label > input:not([type]) { min-width: 260px }` 是给**整行单个输入框**定的；但前缀/后缀在 `.two-col` 里并排，每个 `label` 只有 302px（列 1 文本占 168px，列 2 只剩 126px）→ 260px 的输入框**撑出 134px**，压住右列标签与输入框（相交 2304px²）。
**修法**：① `.export-tab-body .two-col label > input` 放开 `min-width`；② 仅放开最小宽还不够（列 1 是 `max-content`、列 2 带 120px 下限，窄栏下两列本身就溢出）→ `@media (max-width:1599px)` 下把该行改为**各占整行**，输入框反而从 126px 变成 410px 更好用。复测：撑破 **134px → 0**、压后缀 **2304px² → 0**。

### D4 「备注」框最后 9px 被底部按钮行盖住

**根因**：`.footer-actions` 是 `position:absolute`（相对 `.tab-body`，高 49 + `bottom:14px` = 占 63px），而 `.tab-body` 下内边距只有 54px，且按钮行有**不透明底色** → 直接盖住备注框底部 9px（相交 5256px²）。
**修法**：`.app-workspace .export-right .tab-body { padding-bottom: 72px }`（只影响导出页，其它 `.tab-body` 页面不受影响）。复测：**5256px² → 0**。

### D5 导出页主壳把右栏整体推出视口（D2 的同一根因，单独列出以记录表征）

审计里表现为 `section.export-right` 与 `#exportTaskPanel` **出界 158px（1440）/ 232px（1366）**；随 D2 一并解决，修复后该两项从 C 类清单消失。

### 非导出页的逐条判定

- **N1 · 顶栏 ribbon「未开放」徽标溢出导航行 32px（api / feedback / index / export，8 处）**
  `.module-status { display:inline-block }` 挂在 ribbon 项（图标 + 文字 + 徽标）里，项被撑到 ~82px，而 ribbon 行只有 50px → 徽标**跨过导航栏下边框**露到内容区（实拍确认）。**真实但轻微**（都是「未开放」占位页）。建议：给 ribbon 行留高，或把徽标改为不占行的角标。**未改**（会动全局顶栏，先报备）。
- **N2 · 导出页残留：1366×768 下底栏格子仍被裁 9px**
  底栏高度 `clamp(280px,38vh,420px)` = 291.8px 时，`.table-wrap` 的 `min-height:220px` 与所在 1fr 行（220.3px）咬得很紧，叠加 `margin-top:8px` 后仍差 9px。1440×900 与 1080×560 均已是 0。属滚动区底部像素级裁切，**无可见影响**，留作已知项。
- **N3 · tables 表：`.table-detail-view` 内容溢出 10px** —— 空态（「选择表后显示字段结构」）占位块的圆角/内边距，无可见影响。
- **N4 · query 查询：`.sql-editor-bar` 的「排版」按钮与编辑区几何相交 100%（4 处）** —— 实拍确认它是**编辑器右上角的内嵌工具按钮**，正常显示、不遮文字，**设计如此**（已在脚本里加白名单）。
- **N5 · jobs 作业：折叠的 `.log-item` 内部 `.log-body` 仍有 641px 布局高度，溢出父项 636px** —— 在 1400px 高视口下逐项核实：**5 个日志项两两不重叠（overlaps = 0）**，实拍日志列表干净有序，溢出的内容被滚动容器裁掉。判定为**潜在项**（若日志容器滚到折叠项处，可能出现自重叠），当前**未见可见重叠**。
- **N6 · connections 连接 / docs 文档（1080 窄屏）：`.conn-card`、`.docs-nav`、`#docsMain` 溢出父容器 128px / 28px** —— 父容器 `overflow:visible` 且不裁切，元素自然外扩、随后由页面滚动承接，**无可见重叠**。
- **N7 · docs 文档：`.thm-table` 缩略图内容被裁 26px（10 处）** —— 主题预览卡里的**示意图表格**，`overflow:hidden` 是刻意做成缩略效果的，**设计如此**。
