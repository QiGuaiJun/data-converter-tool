## 二、关键风险排查

### 🟢 已经过验证的产品亮点（建议作为上线宣传亮点）

1. **真删表 / 真写库前的强制预演**：导出和同步模块都有「预览/预演」接口，预演里校验不通过会抛 `ValueError`，与"点执行"的错误提示语义一致。
2. **三层 FD 防护**（已经过 2026-09-30 真实事故验证）：
   - `_ClosingConnection` 修根因（83 个 `with connect_db()` 调用点 1 处改）
   - `ResilientHTTPServer` 在 accept 失败连续 100 次（约 20s）**主动 `os._exit(1)`** 把进程交回 systemd 重启
   - systemd `LimitNOFILE=65536` 留缓冲
3. **认证 fail-closed 设计**：`DC_DEFAULT_ROLE` 拼错或留空一律回落到 `viewer`（最小权限），不会意外放开。
4. **公开注册可一键关**：`DC_SIGNUP_CODE` 留空 → 任何人自助注册，默认 viewer；填上 → 邀请制。
5. **脚本通道保留 HTTP Basic**：`acceptance/` 复跑脚本与健康检查能复用 `ADMIN_USER` / `ADMIN_PASSWORD` 无需改造。

### 🟠 高（24h 内整改）

#### H-1：`public/favicon.svg` 缺失 → 测试用例失败

**事实**

- `public/` 根目录有 `favicon-32.png`（1407B）、`favicon-16.png`（523B）、`favicon-48.png`（2342B）、`favicon.ico`（4326B），**没有 `favicon.svg`**。
- 测试 `tests/test_p5_auth.py:289-292`：
  ```python
  def test_static_assets_are_not_blocked(client):
      for path in ("/styles.css", "/shell.js", "/favicon.svg"):
          status, _, _ = client.request("GET", path)
          assert status == 200, f"{path} 应放行（否则登录页自身样式加载不了）"
  ```
- 失败：`/favicon.svg` 期望 200、实际 404。

**生产影响**：**零**。
- 实际前端只引用 `favicon-32.png` / `favicon-16.png`（`public/index.html:7-8` 已用 `?v=20261015_caprine` 缓存键）。
- 浏览器看到 404 不会破坏登录流程，仅缺少"高分屏矢量图标"。

**CI 影响**：让产品经理误以为"代码出 bug"，上线绿灯被打红。

**二选一解决（推荐方案 B）**

- 方案 A：从 PNG 系列合成一份 `public/favicon.svg`，矢量+高分屏友好，保留测试期望。
- **方案 B（推荐）**：修正 `tests/test_p5_auth.py:290` 中的元组改为 PNG/ICO：
  ```python
  for path in ("/styles.css", "/shell.js", "/favicon-32.png", "/favicon-16.png", "/favicon.ico"):
  ```
  理由：PNG 系列已存在且前端已引用，`favicon.svg` 是 README 中"图标定稿"工作流的尾巴（"选定后只留 favicon.svg，整个目录删掉" —— 这一步从未闭环）。

### 🟡 中（1 周内改进）

#### M-1：`.dockerignore` 未排除 `runtime/`

**事实**

当前 `.dockerignore`（`d:/ProjectDevelopment/data-converter-tool/.dockerignore`）只忽略根目录的 `data/uploads/exports/logs`：

```gitignore
.git
.venv
__pycache__
*.pyc
data
uploads
exports
logs
.env
.env.*
!*.example
*.db
*.sqlite
*.sqlite3
```

**问题**：项目自 2026-09-17 起数据落到 `runtime/data/...`，`Dockerfile` 用 `COPY . .`，**会把 `runtime/`（含真实数据库/上传源/导出结果）整个拷进镜像**。

**影响路径**：仅本地手动 `docker build`；Render/Railway 走 `git clone`，已被 `.gitignore` 屏蔽。

**修法**

`.dockerignore` 补充：

```gitignore
runtime/
deployment-data/
acceptance/
archive/
```

这样 `Dockerfile` 不论走哪种部署链路，都不会带运行数据/历史演练产物。

#### M-2：同步模块端到端测试只靠 `acceptance/verify_sync_real_pair.py`

**事实**

`tests/test_p8_sync.py:7-8` 注释明确写：

> 真实 MySQL 链路验证不放这里（单测必须能在没有 MySQL 的机器上跑）—— 那是 `acceptance/verify_sync_real_pair.py`。

**问题**：`handle_sync_run`（`server.py:10812`）的真删表 / 真写库路径无单测守门，一旦改动 sync 数据模型或 mode 语义，要发现回归只能跑人工 acceptance 脚本。

**修法**

- 把"自动建表 / 真实指纹比对"用 SQLite-shim + fixture 数据库包装成 pytest，约 8-10 条新用例；
- 保留 `verify_sync_real_pair.py` 跑真 MySQL，做端到端金标。

## 三、上线前的硬检查清单（建议产品经理把关）

### 3.1 认证自检（必须做）

部署完打开浏览器访问 `https://<IP>/api/connections`，**必须返回 401**（不是 200）。

> README 已经强调，但建议做成"部署完第一次访问的引导页"——未登录访问 `/` 时自动引导到"自检通过了吗？"的页面，不放过去。

### 3.2 依赖与镜像

- 在 `.env` / Render 控制台标注使用的 pip 镜像（`tencent-cloud-setup.sh` 默认腾讯云 `https://mirrors.cloud.tencent.com/pypi/simple`）。
- 在 `requirements.txt` 顶部加镜像来源注释。

### 3.3 数据安全

- 公网部署前，确认数据库连接用的是**业务库专用最小权限账号**（不要 root）。
- 开启 `APP_AUTH_ENABLED=true` + 强制 `ADMIN_PASSWORD`（24+ 字符）。
- 在审计页面检查第一次登录后的「导出敏感表」是否有预期操作被记录。

### 3.4 看门狗自检

- 重启后用 `curl -f -m 90 https://<IP>/api/ping` 验证 90s 内可响应（与 nginx `proxy_read_timeout=1800` 配合验证"进程是否真活着"）。

### 3.5 灾备

- 在 Render / Railway 控制台检查 1GB 磁盘已绑定（`render.yaml:36-39` 已声明）。
- 跑一次 `python scripts/create_data_backup.py --include-uploads --include-exports`，把备份 zip 单独存到 OSS，不要只挂在 instance。
