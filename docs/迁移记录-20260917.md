## 代码改了什么

### 1. 数据落点默认值（`server.py`）

```python
RUNTIME_ROOT = ROOT / "runtime"

def runtime_path(name: str) -> Path:
    return RUNTIME_ROOT / name
```

原来 `DATA / UPLOADS / EXPORTS` 默认落在 `ROOT/data`（源码目录里）。
现在默认落在**项目内 `runtime/`**，任何启动方式（`.bat` / 直接 `python server.py` / watchdog）
算出来的都是同一个目录，不会分裂出第二份数据库。

`DATA_DIR` / `UPLOADS_DIR` / `EXPORTS_DIR` 三个环境变量**优先级不变**，仍然可以覆盖。
容器部署（Docker `WORKDIR /app`）随之落在 `/app/runtime/...`。

### 2. 启动日志打印实际数据目录（`server.py::main`）

```
数据目录 DATA_DIR      = D:\ProjectDevelopment\data-converter-tool-data\data
上传目录 UPLOADS_DIR   = D:\ProjectDevelopment\data-converter-tool-data\uploads
导出目录 EXPORTS_DIR   = D:\ProjectDevelopment\data-converter-tool-data\exports
元数据库 DB_PATH       = D:\ProjectDevelopment\data-converter-tool-data\data\imports.db
```

数据目录一旦分裂，症状是"数据没更新"而不是报错，极难排查。让路径在启动第一屏可见。

### 3. watchdog 与桌面启动器同步同一套规则

`scripts/watchdog_server.py` 的 `_resolve_data_dir()`、`desktop_launcher.py` 的
`runtime_data_root()` 与 `server.py` 的 `runtime_path()` 规则一致。
watchdog 拉起服务时还会**显式传 `DATA_DIR`**，不依赖两边各算一次恰好一致。

### 4. 测试结构

测试从项目根移进 `tests/`，新增 `tests/conftest.py` 把项目根放进 `sys.path`
（原先靠"和 server.py 同目录"这一隐式行为才能 `import server`），
新增 `pytest.ini` 固定 `testpaths = tests`。
