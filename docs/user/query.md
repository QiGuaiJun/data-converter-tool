# 数据查询

## 1. 功能说明

「数据查询」让你对一个已连接数据库执行 SQL 并查看结果。支持**任意 SQL**：只读查询、建表 / 改表 / 删表、增删改，以及多语句脚本逐条执行。可保存常用查询便于复用，也可把查询结果直接转到导出。

> 权限提醒：账号角色决定能执行什么。**只读**账号只能执行 SELECT / SHOW / EXPLAIN 这类只读语句，写语句会被服务端拒绝；**可写**及以上才能执行 DDL / DML。见《登录与账号》。

## 2. 适用场景

- 当前版本功能说明：**已实现**（查询模块支持任意 SQL，含多语句与事务控制）。
- 什么时候使用：
  - 快速查看某张表的数据。
  - 排查导入 / 导出后的数据是否正确。
  - 需要写一段 SQL 得到结果后导出成文件。
  - 临时建表 / 加字段 / 清洗数据（需要「可写」角色）。

## 3. 操作入口

数据导表工具 → 顶栏/侧栏「查询」。

## 4. 操作步骤

### 第一步：选择连接

在「数据库连接」下拉中选择要查询的连接。

**预期结果：** 目标连接被选中。

### 第二步：编写 SQL

在查询输入框输入 SQL。可以是一条，也可以是多条（用分号分隔）。

**预期结果：** SQL 已填写。

### 第三步：执行

点击「执行查询」（快捷键 Ctrl + Enter）。

**预期结果：** 逐条执行，每条语句都会回报自己的结果：查询语句给出结果集，写入语句给出「影响 N 行」，建表 / 改表给出 DDL 完成信息；界面按语句列出摘要与耗时。

### 第四步：高风险语句二次确认

执行 DROP / TRUNCATE / ALTER / GRANT / 无 WHERE 的 UPDATE、DELETE 时，界面会先弹确认框，确认后才真正下发。

**预期结果：** 未确认则一条都不执行。

### 第五步：保存 / 复用（可选）

填写「查询名称」，点击「保存查询」。之后可在「已保存查询」中选择并一键回填执行。

**预期结果：** 查询被保存，之后可复用。

### 第六步：转到导出（可选）

点击「转到导出」，把当前查询结果交给导出模块生成文件（仅支持查询语句作为导出源）。

**预期结果：** 导出页以该查询为源，可继续导出。

## 5. 参数说明

| 参数 | 说明 | 是否必填 | 示例 |
|---|---|---|---|
| 数据库连接 | 查询哪个连接 | 是 | 线上销售库 |
| SQL | 任意 SQL，可用分号分隔多条 | 是 | select * from sales where amount > 0 |
| 查询名称 | 保存查询时使用 | 保存时必填 | 大额订单 |

> 危险语句（DROP / TRUNCATE / ALTER / 无 WHERE 的删改）需要二次确认；只读角色执行写语句会被直接拒绝。

## 6. 执行结果

- 查询语句：结果表格展示数据，显示行数（rowCount）与耗时（elapsedMs）。
- 写入语句：显示影响行数（affectedRows）。
- 多条语句：按顺序逐条执行并分别回报；某条失败时给出失败序号与该条的错误信息，**前面已成功的语句不会回滚**（除非你自己写了 BEGIN / COMMIT）。
- 结果过多时可能截断（truncated 标志），需用条件缩小范围，或改用导出。

## 7. 注意事项

- 工具无法撤销写操作。MySQL 的 DDL（CREATE / DROP / ALTER）会隐式提交，`ROLLBACK` 撤不回来。
- 多条语句不是原子的：要么自己写事务，要么一条一条执行。
- 结果过多会被截断，建议加 WHERE 条件或用导出分批。
- 保存的查询在执行时基于当前选择的连接，切换连接前请确认。
- 保存的查询若含写语句，它变成定时任务后会**周期性执行**，保存前请确认。

## 8. 常见问题

### Q：执行查询报语法错误？

**可能原因：** 表字段名写错、连接名拼写错误、SQL 方言与目标数据库不匹配（MySQL 与 SQLite 的语法有差异）。

**解决方法：** 在「数据表」页确认表名与字段名，检查连接类型与 SQL 是否符合该数据库。

### Q：提示「只读账号只能执行查询语句」？

**可能原因：** 当前登录账号角色是「只读」。

**解决方法：** 让管理员在「账号管理」里把角色改为「可写」；若只是查数据，用 SELECT 即可。

### Q：结果被截断了？

**可能原因：** 返回行数过多，默认只展示部分结果。

**解决方法：** 在 SQL 加条件缩小范围，或导出为文件查看完整数据。

### Q：执行多条语句时中间一条失败了？

**可能原因：** 脚本不是原子的——失败前已执行的语句**已经生效**。

**解决方法：** 先看清失败序号与错误信息，再手工修正；后续脚本建议用 `BEGIN ... COMMIT` 包起来。
