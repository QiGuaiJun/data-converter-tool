# 数据导入

## 1. 功能说明

「数据导入」把 Excel、CSV、TXT、JSON、XML、DBF 等文件中的数据写入数据库表。你可以把文件导入连接过的 MySQL 数据库，或导入本地 SQLite。导入前可预览解析结果、调整字段匹配、选择导入模式，并可通过高级选项清洗数据。

## 2. 适用场景

- 当前版本功能说明：**已实现**（数据导入完整可用）。
- 什么时候使用：
  - 把日常报表 / 表格数据批量写入数据库。
  - 把多个文件（Excel / CSV / TXT）写入同一连接下的表。
  - 需要按字段映射、去重、补空、指定类型时。

## 3. 操作入口

数据导表工具 → 顶栏/侧栏「导入」。

## 4. 操作步骤

### 第一步：选择源文件

在导入页的源文件区域，点「选择文件」选中本机文件，或「选择目录」一次导入多个文件。工具支持 `.csv .txt .xlsx .xlsm .xls .json .xml .dbf`。

**预期结果：** 选中的文件出现在文件列表，工具读取并识别列名。

### 第二步：选择目标库

在「目标连接」下拉中选择已保存的连接；确认「MySQL」或「本地 SQLite」为目标类型。

**预期结果：** 目标连接被选中，下方目标表可供选择或填写。

### 第三步：指定目标表

在「目标表」中选「自动生成」，或「手动指定」一个表名（可选择下拉中已有表，也可直接输入新表名，由工具自动建表）。

**预期结果：** 目标表名已确定，若已存在会列出相关字段。

### 第四步：配置字段匹配

在「字段匹配」中选择「自动 / 按名称 / 按顺序 / 自定义」。可点「...」打开「字段映射」弹窗：调整字段名、跳过字段、设置默认值、指定更新匹配键。

**预期结果：** 源文件列与目标表字段正确对应。

### 第五步：选择导入模式

在「导入模式」中选择（详见参数说明；「覆盖 / 重建」会删数据）。

**预期结果：** 你清楚当前模式对目标表的影响。

### 第六步（可选）：配置高级选项

在右侧「Excel选项 / 数据清洗选项 / 数据库选项 / 其他选项」标签页中按需配置读取引擎、去重、补空、日期列、提交批次等。

**预期结果：** 高级规则已按需启用。

### 第七步：预览

点击「预览」，核对解析后的字段与数据、目标表结构是否符合预期。

**预期结果：** 预览表格展示将要写入的数据与目标字段类型。

### 第八步：开始导入

确认无误后点击「开始导入」。

**预期结果：** 显示导入进度、写入行数、耗时；失败任务会记录原因。

### 第九步：检查结果

用「数据表」或「查询」核对写入的数据。

**预期结果：** 数据已入库且符合预期。

## 5. 参数说明

### 源与目标

| 参数 | 说明 | 是否必填 | 示例 |
|---|---|---|---|
| 源文件 | 要导入的文件（csv/txt/xlsx/xlsm/xls/json/xml/dbf） | 是 | 报表.xlsx |
| 目标连接 | 写入哪个连接（MySQL / SQLite） | 是 | 线上销售库 |
| 目标表 | 目标表名；可自动生成或手动指定 | 是 | sales_2026 |
| 目标库类型 | MySQL 或本地 SQLite | 是 | MySQL |

### 字段匹配

| 参数 | 说明 | 是否必填 | 示例 |
|---|---|---|---|
| 匹配方式 | 按名称 / 按顺序 / 自定义 | 否 | 按名称 |
| 字段映射 | 弹窗中调整字段名、跳过字段、默认值、更新匹配键 | 否 | 略 |

### 数据类型

| 参数 | 说明 | 是否必填 |
|---|---|---|
| 全部使用文本类型 | 所有字段按文本处理 | 否 |
| 自动识别数字及日期类型 | 按内容自动推断数字 / 日期 | 否（默认） |

### 导入模式（危险操作重点）

| 模式 | 实际效果 | 使用建议 |
|---|---|---|
| 追加 | 在目标表已有数据后继续写入 | 日常增量导入 |
| 更新 | 更新目标表相同记录，并添加新记录 | 需要根据更新匹配键做更新 |
| 覆盖 | **删除目标表全部记录后重新导入** | 全量刷新（会删已有数据） |
| 重建 | **删除并重新创建目标表后重新导入** | 表结构也要重新生成（会删表与数据） |

> ⚠️ 危险操作注意
>
> 「覆盖」会删除目标表原有数据再导入；「重建」会删除并重建目标表。
> 如果目标表数据尚未备份，请不要使用「覆盖」或「重建」，否则可能造成数据丢失。

### 高级选项（数据清洗、数据库、其他）

| 参数 | 说明 |
|---|---|
| 替换空白单元格 | 将空白单元格替换为指定值 |
| 去重列 | 按这些列去重（可逗号分隔多个列名 / 序号） |
| 补全列 | 用上一行数据补全这些列的空白单元格 |
| 自定义日期格式列 | 指定日期列与格式，如 `日期:%Y/%m/%d` |
| 分批导入 / 提交批次 | 控制写入批次，影响性能与大文件稳定性 |
| 自定义 SQL | 导入当前文件后执行的 SQL |
| 导入时间字段 | 自动写入的导入时间列 |

## 6. 执行结果

- 成功：显示写入行数、耗时、以及是否创建表等信息。
- 失败：记录失败任务并提示原因（如类型不匹配、主键冲突）。

## 7. 注意事项

- 首次使用建议选「追加」，避免误删已有数据。
- 「覆盖 / 重建」前务必确认目标表数据是否需要保留。
- 涉及看目标表结构可先到「数据表」页确认字段类型，避免导入类型不一致。

## 8. 常见问题

### Q：为什么导入失败/部分行没写入？

**可能原因：** 字段类型不匹配、违反主键唯一约束、源文件某些单元格格式无法解析。

**解决方法：** 查看失败记录与错误提示，调整字段映射或改用「追加」后重试。

### Q：导入时间列为什么是文本而非日期？

若自用 SQLite 或老客户端可能表现为文本；MySQL 下导入时间列为 `datetime`。若你遇到时间列类型不对，通常是目标表已存在的旧字段类型所致，可重建表后重导。
