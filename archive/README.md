# archive/ —— 过程留档

这里放的是项目演进过程中的**非运行必需**材料：验收计划、审计脚本与产出、临时还原工作区。
保留是为了日后回溯"当时为什么这么改"，日常开发和部署都不需要读它。

| 路径 | 内容 | 来源 |
|---|---|---|
| `acceptance-plan-final-v5.md` | 验收计划 v5（131 KB），逐条钉住各模块的可验收行为 | 2026-09 开发会话工作区 |
| `audit/` | 审计脚本与产出（106 个文件，4.1 MB） | 同上 |
| `restore/` | 一次性还原工作区（`conv.json` / `janus.data.json` / `out.txt` / `page.html`） | 同上 |
| `migration-backup-20260917/` | 迁移回滚点：改路径前后的两份 `imports.db` + 3 份桌面导出产物备份 | 2026-09-17 迁移 |

## 为什么单独放一个 archive/ 而不是散在根目录

这些文件的共同点是"写完就不再变"，和源码的生命周期不同。放在这里，顶层目录只剩
**一个源码入口（server.py）+ 配置 + 构建文件 + 三个代码目录**，找东西不用在一堆
一次性产物里翻。

`migration-backup-20260917/` 里含**完整数据库副本（加密后的连接密码在内）**，
已在 `.gitignore` 里按 `archive/migration-backup-*/` 整体排除，不会被提交。

如果确认再也不需要回溯（含迁移回滚点），整个 `archive/` 可以直接删掉，不影响任何功能。
